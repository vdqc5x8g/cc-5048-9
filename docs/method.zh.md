# 迟到姿态修正（旋转重投影）方法说明

## 1. 问题与时刻定义

快速转头时，画面在“姿态采样 → GPU 渲染 → 显示”链路上存在固定延迟。
若直接显示按旧姿态渲染的帧，用户会看到画面拖在头部朝向之后。本演示把三个时刻显式区分：

| 符号 | 含义 | 在代码中的来源 |
| --- | --- | --- |
| `t_s` | 姿态采样时刻 | `t_s = t_r − Δ_SR`（滑块可调，默认 5 ms） |
| `t_r` | 原始渲染时刻 | 固定渲染间隔触发（默认 66 ms ≈ 15.2 Hz），见 `main.js: renderFrame` |
| `t_p` | 呈现时刻 | 每个 `requestAnimationFrame` 显示帧，重投影与参考直渲均在此刻执行 |

显示帧选择的旧帧满足 `t_r ≤ t_p − latency`（`frameFor`），因此端到端延迟为
`t_p − t_s ≈ latency + Δ_SR`，每个数值都逐帧写入时间表格与 CSV。

原始场景渲染按**固定间隔**调度；显示帧到达时只做重投影，不会因为显示频率高
而偷偷增加场景渲染次数。时间轴面板同时画出三类时刻，可直接核对该约束。

## 2. 坐标系与投影（全链路一致）

- 右手世界坐标系：`+X` 右、`+Y` 上、`-Z` 前；头部位置固定在原点。
- yaw 绕 `+Y`，正角向左转；四元数约定 `(x, y, z, w)`，见 `js/math3d.js`。
- 三个视窗与重投影着色器共用同一透视投影：`fovY = 72°`，`aspect = 640/480`，
  近平面 0.1、远平面 100，NDC z∈[-1,1]。
- 视图矩阵 = 朝向四元数旋转矩阵的逆（`R^T`），场景渲染与重投影射线使用同一约定。

## 3. 重投影推导（片段着色器，`js/reproject.js`）

对呈现帧的每个像素：

1. 由 NDC 与投影参数逆投影出呈现时刻的相机空间射线（相机在原点，方向与深度无关）：
   `d_p = (ndc.x · aspect · tan(fovY/2), ndc.y · tan(fovY/2), -1)`
2. 计算姿态增量四元数（CPU 侧，`main.js`）：
   `Δq = q(t_s)^-1 · q(t_p)`，使 `d_s = Δq · d_p`
   （世界射线 `q_p·d_p` 同时等于 `q_s·d_s`，代入即得）。
3. 把旧相机空间射线重新透视投影回旧帧纹理坐标：
   `u = 0.5 + 0.5 · d_s.x / (aspect·tan·(-d_s.z))`，v 同理。
4. 纹理坐标在 `[0,1]` 内则采样旧纹理；越界像素没有任何真实样本，进入边缘处理。
5. 邻域采样跨越 `[0,1]` 的像素描成黄色边界线，给出“可用视野”的可见轮廓。

边缘处理两种模式（界面可切换）：

- **斜纹标记（默认）**：越界像素写红色斜纹，明确声明该区域不可重建。
- **边缘钳取（声明式）**：采样钳到边缘像素并保留边界线；文案与文档均说明
  这只是边缘拉伸，**不**称为正确重建。

越界像素输出 `alpha=0`，指标统计据此区分有效/越界面积。

## 4. 参考帧与误差度量

- 参考帧在 `t_p` 以最新姿态对同一场景**直接渲染**，仅用于对照与误差计算，
  页面标签明确标注“离线诊断直渲，不参与演示渲染管线”。
- 指标在 160×120 低分辨率目标上计算（每 6 个显示帧回读一次，避免频繁 GPU 同步）：
  - `RMS 色差`：有效像素与参考帧每通道差的均方根（归一化到 [0,1]）。
  - `越界占比`：`alpha=0` 像素比例，即原帧视野之外的面积。
  - 旧帧 RMS 使用同样低分辨率路径，保证两者与参考帧对齐比较。
- “角速度扫描”轨迹令频率在 10 s 内由 0.2 Hz 爬升到 5.2 Hz
  （`trajectory.js: sweepStateAt`，相位按积分保持连续），
  曲线图横轴为采样序号、覆盖的 `|ω|` 范围在角注中给出。

## 5. 为什么不能靠提高渲染频率替代

提高渲染频率只能缩小 `t_p − t_s`，并不能消除呈现时刻与采样时刻之间的姿态差；
本演示刻意把渲染间隔做成可调且固定（最低 33 ms），渲染频率在指标卡中实测显示。
重投影发生在显示帧上，与渲染节奏解耦：即便渲染间隔保持 66 ms，
每个显示帧仍以最新姿态完成旋转校正。

## 6. 旋转之外的失效边界

- **头部平移**：平移会产生视差，纯旋转重投影无法恢复被遮挡/未采样的区域。
- **场景物体独立运动**：旧纹理中不存在物体在新时刻的位置，重投影只能旋转整幅画面。
- **大角度旋转**：超过原帧可用视野的部分必然越界，只能标记或钳取。

这些情形不在本初版声明的修复范围内，界面顶部黄色提示与页脚均有同样声明。

## 7. 可重复性与数据真实性

- 轨迹是确定性纯函数（`js/trajectory.js`），同参数同时刻输出完全相同，CLI 可复现。
- 所有画面均由着色器实时生成：按钮只改变仿真状态/uniform，不存在预置帧。
- 逐帧记录可导出 CSV，字段与时间表格一致；CLI `error-table` 用与着色器
  相同的射线投影公式独立核算边界几何，便于交叉验证。
