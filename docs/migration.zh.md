# 图形后端迁移说明：帧令牌、环形槽代际与迟到栅栏

本文档记录重投影图形后端从“隐式纹理轮转”迁移到“显式帧令牌 + 后端适配器”的
设计与核对方法。浏览器（WebGL2）与无头 CLI（CPU 软件后端）实现同一套接口，
迁移正确性由 `cli/migrate-verify.js` 的七个场景独立核对。

## 1. 为什么不能只凭帧号引用纹理

旧实现维护固定数量的离屏纹理，按 `frameNo % slotCount` 轮转。帧记录只保存
帧号和纹理对象引用，存在两个隐患：

1. **槽复用**：第 `slotCount` 帧会覆写第 0 帧的纹理。任何仍持有旧帧号的延迟
   呈现路径，读到的都是**当前槽内容（新帧图像）**，却被当成历史图像。
2. **姿态与纹理脱钩**：提交的颜色纹理、生成时朝向、显示前新姿态三者没有
   显式绑定，等待栅栏与丢弃过时姿态会静默走到同一份纹理，可见结果无法区分。

## 2. 帧令牌与代际（`js/frame-pool.js`）

每次 `submit` 产生一个帧令牌，把三类信息显式关联：

| 字段 | 含义 |
| --- | --- |
| `seq` | 全局递增帧号 |
| `slot` | 环形纹理槽编号 |
| `generation` | 代际；槽每被复用一次自增 |
| `quats` | 生成时（采样时刻 `t_s`）左右眼朝向四元数 |
| `tSampleMs / tRenderMs` | 姿态采样与渲染时刻 |

后端取纹理时核对 `slot.generation === token.generation`，不符即抛
`SlotRecycledError`。**任何路径都不会把当前槽内容返回给旧令牌。**

呈现前的新姿态通过 `ring.deltaFor(token, presentQuats)` 与生成姿态配对，
逐眼计算 `Δq = q_s^-1 · q_p`，再交给后端重投影。

## 3. 栅栏闸门与 wait/discard 策略

- `auto` 闸门：渲染完成即放行（实时演示）。
- `manual` 闸门：栅栏保持等待，由重投影视窗的“放行一个迟到栅栏”按钮单步放行
  （CLI 场景中由 `releaseFence` 驱动）。
- `wait` 策略：目标帧未就绪则呈现挂起，保持上一帧画面，绝不用当前槽顶替。
- `discard` 策略：丢弃姿态过时的未就绪帧，回退到最近一个已放行的帧。

两种策略在“标号不同的两帧交叉完成”场景下产生**不同且各自可核对**的可见结果。

## 4. 两个后端适配器

| 后端 | 文件 | 纹理原点 | 运行环境 |
| --- | --- | --- | --- |
| CPU 软件 | `js/cpu-backend.js` | top-left | Node 与浏览器 |
| WebGL2 | `js/webgl-backend.js` | bottom-left（GL 约定） | 浏览器 |

两者实现同一接口（`renderFrame / isFenceSignaled / releaseFence / blit /
reproject / readMarkers / readSeq / validateToken`），并在 `descriptor`
显式声明原点。CPU 后端的重投影射线数学与 `js/reproject.js` 的 GLSL 逐式对应，
只在读回像素行时做一次原点换算。

## 5. 不对称角标与翻转定位（`js/markers.js`）

中心像素在恒等重投影下恰好不变，无法暴露矩阵或纹理原点翻转。因此每帧双眼各盖
四个**互不相同**的角标：

- 四角基色不同（红/琥珀/绿/蓝）；
- L 形朝向条纹沿该角两条屏边；
- 数据格编码 `眼别(1 位) + 角编号(2 位)`；
- 底边中部帧号条编码实际帧号（10 位 + 起止格）。

核对口径：

- **恒等重投影**（零姿态差）下，四个物理角必须读到各自的正确身份，帧号条必须
  等于呈现帧号——这是后端/原点正确性的判据。
- 注入纹理原点翻转或矩阵翻转时，`diagnoseMarkers` 报告**哪只眼的哪个角先错**
  及推断的翻转类型，而不是依赖中心像素。
- **快速转头**时，呈现帧物理角的射线回查到源帧另一区域是重投影的正确行为；
  落在原帧视野外的角标必须进入无效区（`alpha=0`，红色斜纹/黄色边界），
  帧号条落入无效区时读回 `null`。

## 6. 旧记录读取（只有帧号）

`readLegacyRecord({ frameNo }, ring)` 返回三种状态：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `mapped` | 令牌仍在且代际未变 | 补出代际，可安全取纹理 |
| `recycled` | 令牌在表中但槽已被复用 | 拒绝取当前槽内容 |
| `evicted` | 帧已滚出环形历史 | 历史图像不可恢复 |

## 7. 最小重放（`js/replay.js`）

重放只保存确定性事件（渲染/呈现时刻、四元数、槽、代际、角标与帧号读回），
**不保存整幅纹理**。复放时重新提交渲染、重走环形槽与栅栏：

- `assertGenerationIntact` 校验槽代际随复用单调自增；
- 呈现事件引用被复用槽的旧帧时，重放与后端双双拒绝读取。

## 8. 核对场景（`npm run migrate`）

| 场景 | 核对点 |
| --- | --- |
| 交叉完成与迟到栅栏单步放行 | wait 挂起、discard 回退、单步放行后四角与帧号正确 |
| 快速转头 | 无效区 `alpha=0`、边界外标记、帧号核对、峰值角速度 |
| 环形槽复用不读当前槽内容 | `SlotRecycledError` + 旧记录 `recycled` |
| 纹理原点 / 矩阵翻转定位 | 指出哪只眼的哪个角先错，无翻转对照组通过 |
| 旧/新工程双眼四角 | 纯偏航旧工程与俯仰滚转新工程，双眼各四角身份正确 |
| 含纹理复用的最小重放 | 代际守卫与后端守卫同时拦截旧帧读取 |
